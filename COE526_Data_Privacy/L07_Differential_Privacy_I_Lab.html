01 · Neighbors and a differencing attack

A clinic publishes how many patients have a disease. See how two exact counts can reveal one patient’s secret.

Lab setup. Every dataset and numerical scenario in the experiments is synthetic. No patient, salary, or census microdata is used. True answers are visible to help you learn; a real private release would expose only its protected output.
Key idea. Subtract two exact answers that differ by one person and you learn that person’s data. Differential privacy (DP) stops this by adding random noise.

Words you need

  • D · the real dataset
  • D′ (“D prime”) · the same dataset with one person removed or changed
  • Query f · a question about the data, such as a count
  • Sensitivity Δf · the most one person can change the answer
  • ε (epsilon) · the privacy budget; smaller means more private
  • Noise · a random number added to the true answer
  • Release A(D) · the noisy answer that is published

  2. Select patient F. Why does removing F change the number of people but not the disease count?

Worked explanation and attack terminology

Initially D has six people and three disease-positive records. Removing A gives five people and two positive records; removing F gives five people and three positive records. Both are neighboring pairs. Replacing one record keeps six people and can change the disease count by at most one.

Differencing isolates one person’s contribution. Linkage connects an anonymous record to an identity using other information. Reconstruction recovers many records from many accurate statistics. Membership inference asks whether someone contributed data. DP bounds the effect of participation; it does not prevent all inference about population patterns.

02 · One matching output is not enough

DP asks one question: does any output become much more likely because of one person? Matching at one output (4) is not enough. Every output must be checked.

Key idea. For every output y, the chance with the person and the chance without them must stay within a factor of eε.
Pr[M(D) = y] ≤ eε · Pr[M(D′) = y]

This must hold for every neighboring pair, in both directions. Going further: the general form is Pr[M(D) ∈ S] ≤ eε Pr[M(D′) ∈ S] + δ for every set of outputs S. Pure DP uses δ = 0; this lab uses δ = 0 unless you open the optional δ control. With continuous outputs, compare densities, because the chance of one exact real number is zero.

Each bar is ln(Pr[M(D)=y] / Pr[M(D′)=y]). Pure ε-DP (δ = 0) needs every bar inside the shaded ±ε band. With δ > 0, a coral bar can still be allowed if the total excess probability is at most δ.

03 · Sensitivity comes before noise

Sensitivity is the most one person can change the answer, over every possible dataset. It decides how much noise to add.

Δ1f = maxD ∼ D′ ‖f(D) − f(D′)‖1
Key idea. Count: one person changes it by at most 1, so Δf = 1. Sum of salaries: one person can add up to the cap B, so Δf = B. The cap must be public and chosen before looking at the data.

Choose a bounded query

Public lower bound = 0 SAR. One salary or one category per person. Bounds must be set before examining private data.

For a fixed public n = 6, salaries in [0, 10,000] SAR, and replacement adjacency, what is the sensitivity of the mean?

Hint

Replacing one salary changes the sum by at most B. The mean is the sum divided by n.

Show calculation

Replacing one salary can change the sum by at most 10,000 SAR. Dividing by the fixed public n = 6 gives Δf = 10,000 / 6 ≈ 1,666.67 SAR. This formula does not cover an add/remove mean with a changing private denominator.

    05 · Calibrate and sample Laplace noise

    Now release many noisy answers and look at the pattern. Smaller ε means wider noise: more privacy, less accuracy.

    Could the same output come from D′?

    density of M(D)density of M(D′)inspected output yShaded: 95% of M(D)’s noise mass
    pD(y) / pD′(y)
    = exp((|y − f(D′)| − |y − f(D)|) / b)

    Where does the 95% radius come from?

    For Laplace noise, Pr[|Z| ≤ r] = 1 − exp(−r/b). Set this to 0.95: r = b ln(20) ≈ 2.996b. This is a probability statement before sampling; it does not guarantee that every realized error falls in the range. E[|Z|] = b and SD(Z) = √2 b.

    Try it.
    1. Choose “Lecture count”. Set ε = 0.25 and press “Simulate 1,000 answers”. Note the mean absolute error and b.
    2. Set ε = 1 (this clears the samples) and simulate again. Is the error smaller or bigger?
    3. Check: the mean absolute error should be close to b both times.
    Simulation is not a protected data service. These independent experiments reveal their synthetic truth. Each fresh release on a real dataset would consume privacy budget; seeing 1,000 outputs is not the same as seeing one output. Changing parameters clears this module’s sample display.

    06 · Release a histogram as one vector

    A city publishes population counts by age band. Each person belongs to exactly one of four public categories.

    Key idea. Add noise to every bin. Because each person is in only one bin, the whole histogram costs ε once, not once per bin.

    True synthetic countDisplayed outputRaw noisy value ± 95% noise radius
    Age bandTrueRaw noisyDisplayed

    Public bins, bounded contribution

    Removing one person changes one bin by 1. A replacement can move a person between two bins, changing the vector’s L₁ norm by 2. Independent Laplace noise with scale Δ₁/ε is added to every coordinate.

    Changing this display option reuses the same noisy vector. It does not query the original records again.

    Changing ε or adjacency starts a new synthetic histogram sandbox. In a real release system, changing these settings would not erase earlier privacy loss. The categories are fixed publicly. Clamping and rounding are post-processing, but they may introduce bias. The displayed total need not equal 30. Forcing it to match a private true total is not free post-processing.

    Why not charge ε once for each bin?

    The whole histogram is analyzed as one vector query with global L₁ sensitivity. Under add/remove adjacency, a person changes only one coordinate, so scale 1/ε protects the full vector. Under replacement, a person can change two coordinates, so scale 2/ε is used.

    Try it.
    1. Press “Release a new histogram”. Compare the true and noisy columns.
    2. Untick “Round and clamp”. Raw values can be negative or decimals. Tick it again: the noise is the same, only the display changes.
    3. Switch to “Replace one record”. Why does b double?

    07 · Spend, reuse, and compose

    Fresh noise does not give free repeated queries. A privacy accountant tracks releases made about the same people.

    Key idea. Every fresh noisy answer spends ε, and the costs add up: 4 releases at ε = 0.3 cost 1.2. Reusing an answer you already published is free.

    What if an analyst averages q releases?

    Purple (left axis): theoretical standard deviation of the average of q independent Laplace releases. Coral dashed (right axis): the basic sequential-composition ε bound. Neither line estimates a real attack.

    SD(average) = √2 b / √q

    Basic composition and post-processing

    For releases on the same people, basic sequential composition gives an upper bound εtotal = Σεi. For approximate DP it also gives δtotal = Σδi. Averaging released answers does not add further privacy loss beyond the releases themselves.

    When mechanisms act on disjoint groups of people, parallel composition can use the largest group ε rather than the sum, under the corresponding person-level adjacency. Disjoint rows are insufficient if a person appears in several groups.

    Try it.
    1. Press “Make fresh release” six times with ε = 0.5. Watch the budget bar fill.
    2. Try a seventh release. What happens? Then press “Reuse last release”: does ε spent change?
    3. On the right, switch to “Share fixed total ε”. Does averaging more releases still help?

    Check the total budget

    A count is released four times on the same people, each with ε = 0.3. What is the basic sequential-composition ε bound?

    Hint

    Basic composition: add up the ε of every release.

    Show calculation

    εtotal ≤ 4 × 0.3 = 1.2. Reformatting or averaging those four stored outputs does not require another query and adds no further ε.

    08 · Real applications and your lab report

    Connect the experiments to documented uses of differential privacy, then record your choices and observations.

    Key idea. Central DP: a trusted server adds noise once, so answers are accurate. Local DP: each device adds its own noise, so no one needs to be trusted, but answers are noisier.

    Where is the noise added?

    Central DP needs a trusted curator but adds noise once, so it is usually more accurate. Local DP removes that trust assumption at the cost of much more noise. The protected unit also matters: the lab’s central examples protect one person’s record, while Apple’s documented system protects each donation, with a daily limit.

    Documented deployment · central model

    U.S. Census · 2020 statistics

    The 2020 Census used a disclosure-avoidance system based on DP. Its TopDown algorithm takes noisy measurements of key queries and post-processes them into consistent tabulations across a geographic hierarchy.

    Two differences from Activity 06: TopDown accounts for privacy loss with zero-concentrated DP (zCDP), not the pure ε used here, and some statistics were designated invariants by policy, published without noise and excluded from the privacy-loss accounting. This is a historical 2020 example, not a claim about future census policy.

    [S3] TopDown algorithm paper ↗
    Documented deployment · local model

    Apple · popular emoji

    Apple’s technical overview describes estimating popular emoji with local DP. Each device privatizes its contribution with a Count Mean Sketch before sending it; the server only aggregates the randomized reports.

    The overview lists a per-donation budget of ε = 4 for emoji and one donation per day. The guarantee therefore protects each donation; under composition, many days of donations add up. The sketch is more involved than the two-coin classroom procedure, and these documented parameters may not be current.

    [S4] Apple technical overview ↗
    Practical software · bounded aggregates

    Google · DP libraries

    Google publishes open-source libraries for private counts, sums, means, variances and quantiles with Laplace or Gaussian noise. The low-level libraries assume each user contributes a bounded number of rows, but they do not enforce that bound.

    The caller, or an end-to-end framework such as Privacy on Beam or PipelineDP4j, must group by user and limit contributions first. Activity 03 makes this visible: clipping a salary does not limit how many salary records one person contributes.

    Mechanisms beyond this first lab

    Gaussian mechanism: commonly supports approximate (ε,δ)-DP with noise calibrated to L₂ sensitivity and an appropriate accountant. Report noisy max: releases the selected index rather than all noisy scores. Exponential mechanism: selects an outcome using a sensitivity-bounded utility score. DP-SGD: clips per-example or per-person gradients and adds calibrated noise during training. These require their own assumptions and accounting; adding arbitrary noise to a model or prompt does not establish DP.
